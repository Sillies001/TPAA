## 1. 设计裁决

2026-11-08 复核确认：G6～G11 既有本地关闭声明不能证明产品功能完整，G12 仍有正式外部门。当前状态统一为 G6～G11 `IN_PROGRESS_REMEDIATION`、G12 `IN_PROGRESS_EXTERNAL_DOORS_OPEN`、W9 `NO_GO`、`PRODUCT_COMPLETE=false`、`RELEASE_READY=false`。

本增补不降低原 R3.3 门槛。它把 v33 Demo 的页面目标、后端单一 owner、精确上下文、数据真实性和工程证据收敛为同一组可执行约束。具体实施顺序与退出门见：

`docs/plans/TPAA_G6至G12关闭后复核缺口全面整改与再关闭方案_2026-11-08.md`。

## 2. 运行时能力与基线谱系

1. 基线目录名不构成能力激活依据；只接受受信任 `BASELINE_LOCK` 中存在的 approval artifact。
2. 阶段批准必须从 G2 开始连续，出现 G6 已激活而 G5 缺失等谱系断裂时，运行时失败关闭。
3. 阶段激活器不再维护不断扩张的基线名称白名单；其职责是验证对应能力已被谱系解析器准入、组件已配置、路由 ID/权限/审计与机器权威一致。
4. 每个阶段关闭器必须先读取整改状态和真实门禁证据；`IN_PROGRESS`、缺证据或非零退出码均不得生成关闭状态。
5. G10 的 `NOT_ADMITTED` 只能呈现受控不可用，不能作为“26 视图完成”的关闭条件。

## 3. 历史总览与损坏数据

V01 的所有 KPI、趋势、类别、装备和列表必须使用同一精确 Batch 集合。任务/装备指标仅在独立 Metric Definition 明确单位、方向、版本、适用范围和可比性后准入。

Canonical JSON 无法解析或类型不符属于来源损坏：Application/API 必须返回可识别的 DEGRADED/ERROR 原因并审计，不得将损坏行静默排除后继续报告 EMPTY 或较小计数。

## 4. V26 与非发射行为

V26 是训练评估模块 landing。筛选、统计、时间线、列表和详情必须绑定同一 `batch_id/query_context_id`。筛选栏在三主题、Ribbon 两态和高 DPI 下必须可见、可键盘操作且不被裁切。

武器发射事件与非发射训练行为使用不同类别语义；未准入的非发射来源必须明确显示 N_A，不得被统计为武器发射。

V26 的受控查询筛选集合至少包括类别、裁决状态、Attack Cluster、主体、Episode 与 Session Time 范围。主体匹配射手或目标的精确身份；时间范围使用闭区间且必须非负，反向范围失败关闭。所有字段必须参与 query-context/cursor 指纹，防止把旧分页游标用于新筛选上下文。

Canonical `world_relation.properties` 无法解析、不是对象或 WE 关键字段畸形时，V26 返回 DEGRADED/ERROR（HTTP 503 语义），不得将损坏记录静默排除后给出较小统计。

## 5. V24 条件入口

V24 不是直接导航页。唯一合法入口是 V08 中已经后端确认的 BVR 同目标 Attack Cluster。grant 至少绑定 `release_id/context_id/weapon_event_id/attack_cluster_id/perspective`，服务端与 UI 均拒绝直接访问、过期/伪造 grant、Strike target、跨批次和跨上下文请求。

V24 不产生总分。terminal、adjudication、window 三维状态独立；Cluster 只表达关系；缺少几何、共享、序列或 Formation 事实时对应维度单独 N_A。

V24 查询必须携带精确 `context_id`。Cluster 声明的 WE 集合必须完整解析且全部为 BVR；缺失 WE、混入 WVR/Strike、跨批次或 Context 缺失均失败关闭。Formation revision 采用 `[valid_from, valid_to)` 半开区间，必须覆盖 Cluster 内全部发射时刻。

在不引入新业务评分公式的前提下，可从真实事实确定性呈现：发射事件数、首末发射时刻、齐射跨度、相邻发射间隔、是否同目标，以及精确 Formation revision 中各射手的编队/阵营/成员角色和缺失绑定。上述均标记为 `FACTS_ONLY`，不得转换为协同总分。

## 6. V03 精确回放

回放请求的完整主键是：

`release_id + context_id + weapon_event_id + perspective`

API、Application、前端 Gateway、返回栈和深链均必须保存并验证四元组。仅凭 WE ID 的请求不再满足精确回放合同；源 WE 未绑定 Release/Context 时返回冲突/不可用状态，不得猜测 current/latest。

媒体未准入时可以返回诚实空集，但阶段不能因此宣称完整回放已经完成。媒体清单、主时间游标、轨迹、2D/3D 和证据索引完成后才满足 G9 产品退出门。

## 7. GUI Demo 忠实度与视觉证据

1. 26 视图和模块归属只由 `V33_FINAL_VIEW_REGISTRY.json` 提供，验收工具不得维护第二份手写映射。
2. 页面根节点暴露只读 `data-current-view/data-current-module`；截图前必须断言视图 ID、标题、主题和 Ribbon 状态。
3. V24 截图必须走 V08 受控入口。
4. 矩阵工具检测跨视图重复哈希、交互控件裁切、页面溢出和顶层面板重叠；相同截图不得以不同视图标签入库。
5. 自动矩阵只是一道门。最终还必须由真实角色按任务链进行人工视觉/交互验收。

## 8. 正式硬化与 W9

G11 正式关闭至少需要：installed desktop e2e、安装包 smoke、Linux Desktop、Linux Service、SBOM、许可证、漏洞、目标 workload、真实角色视觉验收九项证据全部 PASS。

G12 必须验证 G6～G11 当前关闭证据，而不是引用历史报告。外部门未闭时，W9 固定 `NO_GO`、`PRODUCT_COMPLETE=false`、`RELEASE_READY=false`。生产部署和发布声明仍未授权。
