# R3.3 116指标设计说明与 Family Applicability 增强报告

**基线：** TPAA V8.0 / ED-2.0 / CB-1.4.0  
**Rebaseline：** R3.3_METRIC_DESIGN_GUIDE

## 1. 触发原因

R3.2 已经冻结 116 项指标的算法合同，但 05C 主要是机器 Catalog 的可审阅投影，不能充分回答“指标到底用于哪个系统、为什么需要、相邻指标为何不能互相替代”。`P1-SNS-*` 尤其容易被误解为 generic sensor，虽然其 Range/Azimuth/Elevation/Radial-Velocity 语义实际上对应 RADAR 测量层。

## 2. 本轮新增

- 新增 `05C1_116指标设计意图_适用边界_区别联系与计算方法说明.md`，逐项覆盖 116 指标；
- 每项包含：适用对象、设计定位/原因、区别联系、窗口、输入、Catalog 计算合同镜像、计算解读、有效/N_A、结果解释、Evidence、Golden 意图、发布/长期路线；
- Catalog v1.14.0 新增 `family_applicability_contracts`；
- `P1-SNS-*` 明确为 `system_type=RADAR`；PSV/ESM/DL/FUS 同步明确产品层适用性；
- 新增 CR-031 Metric Family Applicability and Product-Layer Separation。

## 3. 不变项

- P1 指标数量仍为 116；
- 661 个 `(metric_code,input_field)` 绑定不变；
- metric code、semantic ID/version、algorithm ID/version、formula、input_fields 不变；
- 107 NUMERIC + 9 STRUCTURED、104 longitudinal eligible 不变；
- P/M/WS/Stage、Windows/Linux、R39知识保真合同均保持。

## 4. 设计收益

以后开发者不能再仅凭字段名决定“能不能算某指标”。MetricContext 必须先过 Family Applicability Gate，再做输入解析。这样能够避免 RADAR/IRST/EO/ESM/Datalink/Fusion 之间因数据字段相似而发生产品层污染。
