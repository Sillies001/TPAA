# R3.1 跨平台兼容性与逻辑一致性增强报告

**R3.2 注：** 本文记录 R3.1 时点的跨平台增强。R3.1 所称 P1 Catalog “byte-exact”在该时点成立；R3.2 仅对 Catalog 的进度字段/元数据做术语迁移，116 项公式、语义 ID、输入和算法版本未改变，661 个绑定 tuple 未改变。


## 1. 结论

R3 已具有跨平台技术倾向（PySide6/FastAPI、spawn、跨平台 logical hash 等），但没有把 Windows/Linux 写成完整、可审计、可验收的强制产品合同。R3.1 将该要求提升为 Core Baseline 不变量。

## 2. 本轮新增

- Core Baseline：CB-1.1.0 → **CB-1.2.0**；
- 新增 `PLATFORM_COMPATIBILITY_REGISTRY.json`；
- 新增 CR-027 Platform-Neutral Business Core；
- 新增 CR-028 Cross-Platform Logical Equivalence；
- 总体方案新增 §35；
- 工程公共基线新增 §32；
- 05H 新增 §33～39；
- Traceability 增加跨平台链；
- Core Validator 增加 V-PLATFORM-001～006；
- Independent Audit 增加 IA-16～18。

## 3. 强制平台范围

当前强制认证 OS family 为 Windows 与 Linux；最低覆盖 Windows Desktop、Linux Desktop、Windows Service、Linux Service。具体 OS 版本是 certification profile，不把“Linux”理解为所有发行版天然通过。

## 4. 不允许的平台分叉

Domain/Application/World/Stage/Event/Metric/Assessment/Longitudinal/Capability/Release 不得因 OS 改变算法或业务语义。允许差异仅封装于文件系统、进程、锁、凭据、安装包、硬件/GPU/媒体等 Platform Adapter。

## 5. 结果一致性

同一冻结输入在 Windows/Linux 上：离散业务结果 exact parity；数值结果使用相同 Golden tolerance/rounding policy；native package/path/PID 等物理差异不进入业务 logical hash。

## 6. 对既有评价基线的影响

116 项 P1 Metric Catalog 与 661 Input Authority Matrix 保持 byte-exact，不因本轮跨平台增强重新录入或改变算法定义。本轮改变的是运行、适配、CI、打包与验收合同。
