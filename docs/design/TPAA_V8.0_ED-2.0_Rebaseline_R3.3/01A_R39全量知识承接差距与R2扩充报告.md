# R39 全量知识承接差距与 R2 扩充报告

**R3.2 注：** 本文是 R2 历史差距报告；其中旧版 `Phase 1` 等表述按当前术语解释为 **P1**，不构成当前项目进度语言。当前项目进度只使用 M0～M9。


**目的：** 对 R39 中可复用的业务、评价、工程、数据、可视化和扩展知识，与 Rebaseline R1 逐项对比；凡 R1 未承接、承接过浅、只保留占位符或被过度收窄为 P1 的内容，在 R2 中重新纳入受控基线。

**结论摘要：** R1 在 P1 的 116 项性能指标、661 项输入权威、Context/Release/Replay/DTO 等工程收口方面是有效的，但对 R39 的“完整训练评价 + P2～P6 能力智能 + 多层复盘/分析”知识承接不足。R2 不回退到旧版多处重复 schema 的写法，而是把这些知识拆成总体语义、公共工程合同、专业分册和机器可读语义注册表，并保持 P1 两份机器权威字节不变。

## 2. 判定规则

- **充分承接**：R1 已保留语义和工程边界，不需要改变定义权；
- **承接过浅**：R1 有标题/路线/占位，但不足以支撑后续尺寸扩展；
- **未承接**：R39 有明确有效设计，R1 未形成可查阅合同；
- **不直接继承**：R39 中旧字段、重复 current-looking schema、旧 DTO 或尚未冻结的算法细节，不复制；保留其业务意图并重构为新权威。

## 4. 不直接搬运的旧知识

以下内容在 R39 中存在，但 R2 不直接复制：

1. 多份 `CURRENT_LOGICAL_SCHEMA` 或同一实体重复字段表；
2. 旧 DTO 的字段级定义；
3. 与 ED-1.5.12 当前契约冲突的 legacy 字段或 nullability；
4. 尚未达到可验证成熟度的 P2～P6 数值参数/模型超参数；
5. 把结果直接解释为人员能力、把团队结果复制给个人、把 Truth 当成 Perception 的旧式捷径；
6. 将 forecast/counterfactual 与事实产品混合的表达。

这些内容的“业务意图”被保留，但定义权改为 Core/Canonical machine authority。

## 5. R2 的结构性变化

R2 相比 R1 新增/扩充：

- Core Baseline 从 CB-1.0.0 升至 **CB-1.1.0**；
- 总体方案 §§17～19 深化 Basic/WVR/BVR，新增 Strike、四类训练统一框架、四 scope、Assessment Profile、Instructor、P2/P3、Course/Unit、Plugin/Interop 等；
- 新增 **05I 训练效果/Human/Team/Mission/Joint**；
- 新增 **05J Capability/Attribution/Digital Twin/Model Profile**；
- 05A～05H 均增加跨 Phase 尺寸扩展合同；
- 新增四个机器语义注册表；
- Stage Registry 新增 `STRIKE_MISSION_V1`；
- Core Rules 新增 CR-016～CR-026；
- P2～P6 不再只是 roadmap 名称，而是 `DESIGN_CONTRACT_FROZEN`；
- review gates 增加全量知识承接、安全隔离、可辨识性、knowledge-time 和 scope contamination 检查。

## 6. 尺寸扩展原则

R2 的目标不是一次性实现 P2～P6，而是保证未来扩展不需要重新发明语义：

- P1 的 116 指标仍是当前可执行 Catalog；
- P2～P6 先冻结对象、输入/输出、边界、版本、证据和失效语义；
- 当某阶段进入实现时，只新增/升级其机器 artifact 和 schema migration，不允许各分册自行增加一套定义；
- 所有扩展必须通过 authority registry、baseline lock、traceability、review gates 和 cold-start package audit。

## 7. 结论

R1 适合作为“P1 工程合同重构”的成功中间版本，但不应作为 R39 全知识的最终替代。R2 将 R39 的有效知识从“旧大文档中的散布内容”迁移为可扩展的多层受控体系：**事实观测、训练评价、能力估计、团队/任务评价和预测闭环彼此分离，同时保持从证据到结论的可追溯性。**
