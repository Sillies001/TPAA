# G4 v33 批次登记、数据导入与质量闭环设计增补

> 状态：`APPROVED_LOCAL / G4_CLOSURE_INPUT`
> 日期：2026-11-07
> 适用候选：`CB-1.9.0 / DB 1.10.0`
> 边界：仅用于本地开发与验证，不构成发布或生产部署批准。

## 1. 设计目的

本增补把 v33 Demo 的 V23“数据管理与批次导入”落实为可执行产品闭环，补齐此前只有导航和空状态、没有真实批次登记与来源资格处理的问题。实现目标是：原生选择数据源，经短期票据进入 Application 服务，形成稳定 Batch ID，完成解析与资格判定后才进入 V01；训练类型和兵力/编队上下文的后续变化必须追加修订并进入审计链。

## 2. 分层与单一所有者

调用链固定为：

`Qt 原生选择器 → 受控本地动作 → loopback import ticket → GUI API → BatchImportService → SourceWorkflowService / DurableBatchRepository → DB 1.10.0 与对象存储`

- Qt 适配器是本机路径的唯一持有者；浏览器页面、REST DTO、日志和证据不得出现绝对路径。
- `BatchImportService` 是登记状态机、确认规则、稳定 ID、重试和修订语义的唯一所有者。
- `SourceWorkflowService` 继续拥有 CSV 解析、规范化和来源制品写入，不在 GUI/API 重复解析。
- `DurableBatchRepository` 只负责 DB 1.10.0 的持久化、事务和审计，不定义业务默认值。
- V01 只消费 `qualification_status=QUALIFIED` 的 Application 投影。

## 3. 机器权威与兼容性

- 直接父基线：`CB-1.8.0`，不可改写。
- G4 后继候选：`baseline/CB-1.9.0/`。
- 数据库继续使用 G1 已建立的 DB 1.10.0 四张表，不重复创建迁移。
- `BASELINE_LOCK.json`、`GUI_BATCH_IMPORT_AUTHORITY.json`、`G4_BATCH_IMPORT_APPROVAL.json`、路由与权限权威共同构成激活边界。
- 旧的 DB 1.9.0 运行实例通过受控迁移步 `G1-V33-DB-1.10.0` 到达候选迁移头；CB-1.5.0 仍作为该迁移步的不可变来源权威。
- Canonical 加载器只对精确的 CB-1.9.0 名称、锁哈希和 49 个受控制品开启本地候选信任，不接受目录名推断或宽松哈希。

## 4. 批次状态机

状态仅允许：

1. `PENDING_CONFIRMATION`：训练类型为 `UNCLASSIFIED` 且用户尚未确认；禁止解析和进入 V01。
2. `PARSING`：用户已明确确认训练类型，正在执行来源解析与资格判定。
3. `QUALIFIED`：所有票据成员均完成受控解析；允许进入 V01。
4. `FAILED`：解析或资格失败；保留原因码，可在票据有效期内用同一幂等键和不可变 manifest 重试。

允许的迁移为：`PENDING_CONFIRMATION→PARSING`、`PARSING→QUALIFIED/FAILED`、`FAILED→PARSING`。`QUALIFIED` 不允许通过导入接口回退。

## 5. 训练类型和稳定标识

- 训练类型只能为简单对抗、混合对抗、综合对抗或未分类。
- 页面不得预选训练类型。
- 非 `UNCLASSIFIED` 必须同时提交明确确认；`UNCLASSIFIED` 不得伪装为已确认。
- Batch ID 使用 `UUID5(actor, idempotency_key)`，同一行为身份稳定重放；session、日期、manifest 或 actor 漂移时返回幂等冲突。
- 从未分类转为明确类型和合格批次后的类型复核都追加 `batch_training_type_revision`，禁止覆盖历史。

## 6. 文件与目录票据

- 文件选择只接受非空、受大小上限约束的 CSV。
- 目录选择在原生层打包最多 32 个 CSV；ZIP 成员必须为相对路径，拒绝绝对路径、`..`、空成员和非 CSV。
- 票据仅驻留当前后端进程内，默认有效期 600 秒，包含 entry count、总字节数和 manifest SHA-256。
- 页面仅获得 ticket DTO，`local_path` 必须恒为 `null`。
- 本地动作入口使用同源 `/ui?tpaa_native_action=select-file|select-directory` 导航请求；Qt 页面只接受这两个精确值，完成动作后取消导航并向当前文档派发一次性结果事件。

## 7. 兵力与编队上下文

- V23 可为一个 context 追加有效时间修订，不能原地覆盖。
- 成员必须使用唯一 aircraft ID，阵营限制为红方、蓝方、中立、未分配或冲突待裁决。
- 每次修订记录来源、原因、操作者、起止 session time、编队 ID、成员角色及独立目标标志。
- 当前读取返回最新修订；历史修订保留在数据库和审计日志中。

## 8. API 与权限

G4 激活 7 条路由：导入票据、批次列表、批次详情、批次登记、训练类型修订、上下文读取、上下文修订。所有路由同时进入 API 路由权威和安全权威；Desktop/Service 共用 Application 语义。其余 G5+ 路由继续保持保留且不注册。

所有写操作要求受控主体，稳定 route ID 写审计。正文大小、内容类型、UUID、时间区间、成员数量和字符串长度均在服务端失败关闭。错误返回稳定 code、状态和权威 provenance，不回显本机路径或原始异常。

## 9. GUI 行为

- V23 提供文件/目录选择、票据摘要、登记表、显式确认、未分类、失败原因和同身份重试。
- 登记为 `QUALIFIED` 后自动刷新真实批次列表并进入 V01。
- V01 对未确认、解析中和失败批次全部隐藏；空集合显示明确 EMPTY 状态。
- V23 在已有批次上呈现训练类型修订和 Force/Formation Context 修订表单。
- 所有新增可见文本使用中文；必要的 ID、状态码和缩写保留英文。
- 100% 与 150% DPI Windows WebEngine 验收必须覆盖 exact loopback、off-the-record、原生票据、V23→V01、类型修订、上下文修订和正常退出。

- Python 单元、API、持久化、迁移和契约测试；
- TypeScript 类型检查和确定性离线构建；
- Ruff 与 mypy 零失败；
- Windows 100%/150% DPI WebEngine 完整闭环证据和截图；

关闭状态只能写为 `CLOSED_LOCAL_WITH_GATES`，并继续明确 `push=PROHIBITED`、`production_deployment=PROHIBITED`、`release_claim=false`。
