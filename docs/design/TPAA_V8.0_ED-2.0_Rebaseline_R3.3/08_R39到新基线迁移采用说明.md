# R39 → TPAA V8.0 / ED-2.0 Rebaseline R3.3 迁移与采用说明

## 1. R39 的新角色

R39 不再作为 current implementation text 继续逐章节打补丁。它保留为：历史设计依据、语义知识矿山、算法/contract provenance、Golden/回归来源和“哪些错误不能再发生”的失败知识来源。

R3 的目标是**迁移 R39 全部有效知识，而不是迁移其旧文档结构和重复 schema**。

## 2. P1 算法语义与输入绑定保持

- 116 Metric algorithm contracts；
- 661 Input Authority bindings。

R3.2 保持 116 项 metric_code、semantic_id/version、algorithm_id/version、formula、input_fields 与 661 个 `(metric_code,input_field)` 绑定不变；仅将旧 1C/1D/1E 进度元数据迁移为 M/WS 语言。

## 3. R3 新承接的主要知识

- Basic / WVR / BVR / Strike 四类训练；
- Individual / Team / Package / Joint-LVC 四 scope；
- Qualification / Diagnostic Competency / Evidence 三层评价；
- Assessment Profile、教员 review/override/agreement；
- Event Graph、责任属性、候选根因；
- 人员、团队、课程/单位和 cohort 纵向评价；
- P2 Context Attribution / Normalization；
- P3 Capability Model / Surface、Digital Twin、Model Profile；
- P6 Forecast / Counterfactual / Recommendation 的事实隔离；
- Debrief media、bookmark、playlist、positive event；
- Training Plugin、Joint/LVC gateway；
- knowledge-time、evidence independence、identifiability 等安全边界。

R2 的 60 项知识域差距分析保留在 `01A_R39全量知识承接差距与R2扩充报告.md`；R3 的方法/可视化保真修复见 `01B_R39知识保真与可视化保真_R3修复报告.md`。

## 4. 不迁移为 current authority 的内容

- R39 中重复的 current-looking schema；
- 旧 DTO 字段表和不一致 nullability；
- 与已冻结 Core model 冲突的 legacy 字段；
- P2～P6 尚未验证的具体数值模型/超参数；
- 将 Truth 当 Perception、团队结果复制给个人、结果替代过程等不安全捷径。

- 661 输入：`METRIC_INPUT_AUTHORITY_MATRIX.json`；

- C/W/P/A/J/M capability：`WORLD_CAPABILITY_REGISTRY.json`；

- 跨域强制规则：`CORE_RULES.json`。

## 6. 实现团队采用步骤

1. 将 canonical artifacts 和 Baseline Lock 纳入源码库根基线；
2. 对现有 DB/Domain/DTO/API/GUI 做 authority mapping，不从 Markdown 手抄字段；
3. P1 继续执行 116/661 当前合同；
4. P2～P6 在 feature gate 关闭状态下先实现 schema/plugin/API skeleton，不对用户宣称能力可用；
5. 每个 P 能力只能在对应 M 里程碑和所需 WS 的 Gate 闭合后启用；进入实现时补充 versioned executable catalog/model/profile、Golden/validation 和 migration；
6. 任何 historical read 都使用 exact refs，禁止 latest/current fallback；
7. 通过 Core Validator、Independent Audit、Manifest 与 cold-start 后才可形成发布候选。

## 7. 后续变更治理

需求变更顺序固定为：

`Core requirement / machine authority → traceability → professional design → implementation/tests → consolidated projection`。

禁止先在某个专业分册或 GUI/API 中添加“临时字段/临时状态/临时算法”，再事后同步其他文档。新增训练类型优先通过 Training Plugin composition 扩展，而不是绕过 C+TPAA-M 证据主链。


## R3 知识保真迁移

R3 新增方法论与可视化保真层：原 01 的非冲突方法内容由 03A 完整重构；原 04 的非冲突页面/交互/视觉语义由 05G 完整重构。旧字段/DTO/schema 定义不复制，而由 Canonical 替代；该替代不视为知识丢失。详见 `01B_R39知识保真与可视化保真_R3修复报告.md` 与 `canonical/KNOWLEDGE_FIDELITY_MATRIX.json`。


## R3.1 跨平台合同增强

R3.1 不改变 R39→R3 已冻结的评价语义、116 Metric 或 661 Input Authority；它把此前散落于部署/进程/hash 设计中的跨平台考虑提升为正式 Core 合同。Windows/Linux 均为 mandatory OS family，详细权威为 `PLATFORM_COMPATIBILITY_REGISTRY.json`，并由 CR-027/CR-028 与 V-PLATFORM-001..006 持续审查。


## R3.2 P/M/WS/Stage 术语治理

R3.2 正式取消“开发 Phase”“第一～九阶段”和旧 1A～1G 作为 current project progress language。

- P1～P6：能力成熟度/产品 claim level；
- M0～M9：项目开发与验收里程碑；
- WS-*：横向工程工作流；
- Stage：Training Episode 内部训练过程。

历史 R39/R1/R2/R3 报告可保留旧词作为历史证据，但任何 current 计划、Issue、代码字段、CI 状态、Release Note 和验收必须使用上述受控语言。旧 1C/1D/1E 的 current 映射分别为 M2 foundation batch、M3 remainder batch 和 M4 P1 longitudinal。

## R3.3 116指标设计意图与适用性增强

R3.3 新增 `05C1_116指标设计意图_适用边界_区别联系与计算方法说明.md`，逐项覆盖 116 个 P1 指标。它补齐 R3.2 中“算法合同完整但设计意图解释不足”的问题。

本轮 Catalog 从 v1.13.0 升至 v1.14.0，仅新增 family applicability/common-rule 语义：尤其 `P1-SNS-*` 明确为 RADAR sensor detection/measurement。116 个 metric code、semantic_id/version、algorithm_id/version、formula、input_fields 均未改变，661 个 input binding tuple 未改变。
