# ADR-M0-007 — Generated-source Policy

- **Status:** CLOSED
- **Decision date:** 2026-09-21
- **Owner role:** WS-CORE / WS-DEVOPS technical lead
- **Milestone:** M0 Engineering Bootstrap
- **Authority:** SDIB-1.0 §8.4, §9, §15, §17, Appendix F

## Decision

TPAA uses **checked-in generated source plus deterministic regenerate-diff enforcement**.

1. `src/tpaa_generated/` is a machine-generated tree and MUST NOT contain human-authored business logic.
2. Generated Python files are committed to Git to preserve reviewability, offline use and exact release provenance.
3. Every generated Python file carries a deterministic provenance header containing generator id/version and source artifact id/version/SHA-256.
4. Local and CI verification use the same repository commands:
   - `python tools/dev/tpaa_dev.py verify-generated`
   - `python tools/dev/tpaa_dev.py regenerate-diff`
5. CI orchestration MUST invoke the repository `regenerate-diff` command; it MUST NOT reimplement generator semantics in CI-provider configuration.
6. A Canonical change that legitimately changes generated bytes is reviewed with the corresponding Canonical/Baseline Change evidence required by SDIB. Generated-byte changes alone are not authority.
7. Cross-platform “read-only” is enforced by policy and gates, not filesystem permission bits, because Git does not preserve a portable Windows/Linux read-only attribute.

## Rationale

Committing generated projections makes code review, offline bootstrap, import/static analysis and release reconstruction possible without first executing generation. Deterministic regenerate-diff prevents the checked-in projection from drifting from Canonical authority.

Keeping the gate vendor-neutral avoids turning GitHub Actions, GitLab CI or another service into an architectural dependency before CI orchestration is formally selected.

## Rejected alternatives

- **Build-only generated source:** weaker reviewability/offline inspection and requires generation before many static checks; no demonstrated benefit justifies departing from the SDIB default.
- **Generated files ignored by Git:** removes the exact reviewed projection from the release revision.
- **Filesystem read-only bits as enforcement:** not portable or reviewable through Git and can be bypassed locally.
- **Provider-specific generation logic:** risks local/CI semantic drift and creates an unnecessary CI-vendor dependency.

## Reopen conditions

Reopen if generated source ceases to be committed, a mandatory packaging/build environment cannot consume committed projections, provenance requirements change, or a different governance model is approved through SDIB change control.
